# Refactoring & Component Architecture Patterns (`finxui-ref`)

When migrating or refactoring legacy code from `finxui` to `finxui-ref`, AI Agents MUST follow these explicit refactoring patterns and architectural methodologies:

---

## 1. Base UI Primitives & Pure shadcn Enforcement

- **Use Generated shadcn Primitives As-Is**: All UI primitives in `src/components/ui/` MUST be installed directly via `pnpm dlx shadcn@latest add <component>` and MUST remain **100% untouched and unmodified**.
- **No Custom Primitive Overrides**: DO NOT modify generated `src/components/ui/` files, add ad-hoc CSS overrides, or introduce custom third-party wrappers (`sonner`). Always use standard `shadcn` primitives as generated by the CLI.
- **Base UI `render` Prop Pattern**: Always use Base UI's `render={<Component />}` prop pattern for triggers (e.g., `DropdownMenuTrigger`, `TooltipTrigger`, `DialogClose`). DO NOT use legacy `asChild` props.

---

## 2. Decouple Client & Server Module Boundaries

- **Prevent Server-Only Import Leakage**: Keep client-safe application configuration (`src/lib/config.ts`) strictly decoupled from server-only services (`src/lib/services.ts` containing `import "server-only"`).
- **Safe Client Hydration**: Ensure client components (`"use client"`) can safely import global configs, schemas, and launchers without breaking React Server Component (RSC) build boundaries.

---

## 3. Two-Tier Component Layering Architecture

When refactoring a legacy feature, split it cleanly into two separate architectural layers:

1. **Atomic UI Layer (`src/components/ui/`)**:
   - Pure, unpolluted presentational Base UI primitives (`button.tsx`, `dialog.tsx`, `command.tsx`, `dropdown-menu.tsx`).
   - Contains zero business logic, zero Zustand store imports, and zero hardcoded domain data.

2. **Domain Feature Layer (`src/components/`)**:
   - Stateful application components (`global-search.tsx`, `app-topbar.tsx`, `app-sidebar.tsx`, `tab-bar.tsx`).
   - Integrates Zustand stores, role-based access control (RBAC), event listeners (`Ctrl+K`), and screen launchers (`launchScreen`).

---

## 4. Multi-Instance Banking Workbench Pattern

- **Unique Instance Generation**: When refactoring legacy single-tab tracking into the new workbench, update Zustand `addTab` logic to generate a new unique instance ID (`uniqueInstanceId = `${baseId}_${Date.now()}_...``) on every invocation.
- **Clean Title Suffixing**: Store clean titles on state objects and render universal index badges (`1`, `2`, `3`...) or instance numbers dynamically in UI layers.

---

## 5. Deep Legacy Analysis & Pro Architecture Placement

- **No Blind Feature Additions**: NEVER write code blindly. Before adding any new feature, inspect how it was built in the legacy `finxui` codebase.
- **Pro Architecture Analysis**: Analyze how a senior engineer cleanly structures the feature in Next.js App Router + Base UI / shadcn + Tailwind v4 before placing files.
- **Strict File Placement**:
  - Atomic Presentational Primitives → `src/components/ui/`
  - Stateful Feature Components → `src/components/`
  - Core Services & Utilities → `src/lib/`
  - API Route Handlers → `src/app/api/`
- **Track Future TODOs**: If a feature requires future extensions or dependent sub-components, add explicit `// TODO:` comments and log them in tracking docs.
